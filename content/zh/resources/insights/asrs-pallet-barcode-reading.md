**要做好立体库识别，先明确每个工位需要识别什么，再针对实际货载和路线共同确定标签位置、读码器布置及系统响应。** 手持设备能扫出条码可以作为一项参考，但不能单独证明固定读码器在正常运行时能读取正确身份。

本文重点讨论标签位置和漏读排查。[缠绕膜指南]({{< relref "resources/insights/asrs-pallet-stretch-wrap-clearance.md" >}})侧重货载固定和机械接口，并介绍了身份识别的基本检查；当具体问题是如何规划、排查光学条码读取工位时，可继续使用本文。RFID 使用不同技术，需要另行评估。

## 1. 先确定每个条码识别的对象 {#identity}

可重复使用的托盘可以有随托盘保留的**资产编号**；托盘上的货物可以有独立的**物流单元编号**，在重新组托或拆分货载后可能改变。纸箱还可能有自己的商品条码。这些身份不能互换。例如，[GS1 瑞典指南](https://gs1.se/en/guides/how-to-guides/labeling-the-pallet/rules-and-recommendations/)将 SSCC 用作物流单元的标识；它不会因此把托盘资产编号变成货载编号。

在入库、转运或空托回收等各工位，与系统责任方约定预期身份、支持的条码类型和数据格式，以及托盘与货载的关联如何建立、变更和解除。记录未读到条码、读到多个条码、读到有效但非预期的条码，或读取结果与仓储记录不符时分别如何处理。解码成功不等于关联关系正确。

## 2. 在同一张路线图上标出标签和读码器 {#placement}

在实际托盘和完整货载上标记一个参考面。对每个工位画出运行方向、是否转向、计划贴码表面以及读码器位置。以约定基准记录标签高度和方向，以及托盘位置的预计变化范围。请设备供应商确认完整变化范围是否位于已安装设备的读码视野和对焦条件内。

| 需要回答的问题 | 与责任方共同确认的内容 |
| --- | --- |
| 贴在哪个表面？ | 实际托盘或货载上的稳定区域，具有容纳完整条码及所需空白区的空间。 |
| 面向哪一侧？ | 经过转运和转向后，各读码器实际看到哪一面；是否允许多个标签，以及如何处理相同或不同条码。 |
| 什么可能遮挡？ | 缠绕膜褶皱、打包带、相邻纸箱、超出边缘的货物、污渍或导向件可能遮挡或改变视野；应检查完整货载，而不只看空托。 |
| 什么可能损坏标签？ | 搬运接触、清洗、储存和更换标签可能影响所选表面与胶粘方式。索取代表性样品并约定表面准备方法。 |
| 适用什么规则？ | 分别核对适用的条码规范、交易伙伴要求和现场读码器的视野范围。 |

如果采用 GS1 物流标签，应核对当前适用的 GS1 规则及交易伙伴要求：[GS1 物流标签指南第 8 节](https://ref.gs1.org/guidelines/logistic-label/)说明了物流单元标签的位置。这不是要求所有可重复使用托盘的资产标签都贴在同一高度的通用规则，也不能证明某个立体库读码器一定看得到。

## 3. 区分漏读、读错和系统拒收 {#diagnosis}

在指定安全工位保留标签、货载方向、事件时间和工位编号。如系统有相关记录，请设备责任方提供读码图像、解码值、错误和后续系统事件。不要伸入运行设备，也不要绕过防护、联锁或现场暂扣程序。

| 现象 | 下一步核查 |
| --- | --- |
| 没有图像或图像中没有条码 | 是否触发读码？预期的一面在当时位置是否进入读码视野？请系统责任方检查记录。 |
| 看得到条码但无法解码 | 完整条码及空白区是否可见且完好？与正常标签比较褶皱、反光或遮挡，请读码设备供应商分析图像。 |
| 解码成功但系统拒收 | 将完整读取值及格式与预期身份和工位记录比较：是否读到了纸箱条码或旧标签？ |
| 读对编号但显示错误货载 | 请仓储系统责任方核对关联关系与事件顺序，包括组托、拆分和托盘重复使用。 |
| 偶发成功或失败 | 对比通过与拒收货载的位置、方向、速度、标签状态、缠绕膜及光照，再判断原因。 |

[GS1 条码质量指南](https://support.gs1.org/support/solutions/articles/43000734141-what-should-i-check-to-ensure-good-quality-barcodes-)将空白区、对比度、损伤、包装遮挡和位置列为检查项。[Cognex 的 DataMan 诊断说明](https://docs.cognex.com/dmst_2520/web/EN/DMST_QANDA/Content/Topics/idp10153570832.htm?TocPath=Optimize+Image%7C_____31)展示了其读码工具中条码被截断、标签折皱和空白区不足等例子。它们不能证明某次故障的原因；应以现场设备资料和事件记录为准。

## 4. 分别检查印刷质量和实际运行识读 {#verification}

手持扫码有助于比较标签，但它不是印刷质量等级，也不能代替固定读码器验收。需要正式评估条码质量时，应请标签供应商或具备能力的验证方确认适用方法并提供结果。[GS1 说明](https://support.gs1.org/support/solutions/articles/43000734152-how-can-i-measure-the-quality-of-my-printed-barcodes-)，符合要求的验证设备可测量条码参数并给出等级；所需等级取决于应用。等级合格仍不能证明现场读码器看到了正确条码，也不能证明仓储记录正确。

## 5. 约定代表性试验和异常处理 {#trial}

与系统及包装责任方共同记录托盘系列、型号和图纸版本、标签规格及位置和方向、读码器和工位编号，以及预期读取的身份。试验应包括有实际缠绕膜及标签的**代表性完整货载**；需要读取空托回程时也应包括空托。纳入允许的位置及方向变化、相关转运与转向点，以及约定的运行顺序。

每次通过应记录预期与实际读取值、工位事件和最终仓储关联。样本数量、重复次数及验收标准由项目系统责任方确定。遇到条码无法读取或出现非预期值时，按现场批准程序暂扣并处理；不要为了让货载通过而擅自调整读码器或更换标签。将记录与[样品测试清单]({{< relref "resources/insights/asrs-pallet-sample-testing-checklist.md" >}})一并保存；标签、托盘、缠绕膜、读码器或路线变化时，复核相关检查是否需要重做。

## 准备询价资料 {#enquiry}

向托盘供应商提供标出计划贴码表面的图纸或照片、托盘配置、搬运接触位置、清洗条件，以及标签是否需随可重复使用托盘保留。向系统供应商提供路线、读码器位置、预期识别对象、完整货载照片和适用标签规范。[联系宝恒]({{< relref "contact.md" >}})可讨论候选托盘配置及样品评估所需资料；标签或标识方案及项目适配性需按订单确认。
